===== launcher script pattern (all 6 identical modulo progdir; Clock.sh verbatim) =====
#!/bin/bash
progdir="$(cd $(dirname "$0") || exit; pwd)"/clock
export PYSDL2_DLL_PATH="/usr/lib"
program="python3 ${progdir}/main.py"
log_file="${progdir}/log.txt"
[ -f /mnt/mod/ctrl/volumeCtrl.dge ] && /mnt/mod/ctrl/volumeCtrl.dge &
$program > "$log_file" 2>&1
kill -9 $(pidof volumeCtrl.dge)
# Modified_System_Tools.sh additionally handles random.cfg -> random.sh, exit 0.

===== execution mechanism (dmenu EXITS before app runs) =====
Chain: launcher.service -> launcher.sh -> loadapp.sh -> dmenu_ln -> dmenu.bin (ALL root).
/mnt/vendor/ctrl/dmenu_ln (verbatim, key function):
  ACT="/tmp/.next"; CMD="/mnt/vendor/bin/dmenu.bin"
  app_scheduling(): if $CMD >/dev/null 2>&1; then
      if [ -f "$ACT" ]; then sh $ACT >/dev/null 2>&1; ... fi
    else sleep 30; fi
  # loadapp.sh loops `while [ -f $RunBin ]; do $RunBin; done` so when the app
  # script finishes, dmenu_ln returns and dmenu.bin RESTARTS (frontend return, no reboot).
- dmenu writes its next action to /tmp/.next (strings: `chmod 777 /tmp/.next`,
  `cd %s`, `"%s"  "%s"  `), then EXITS 0; the wrapper runs `sh /tmp/.next`.
- APPS .sh files are executed directly (see /mnt/mod/ctrl/apps: `/mnt/mmc/Roms/APPS/$file`).
- stdout of BOTH dmenu and app goes to /dev/null (confirmed in wrapper) -> log to files.
- Env provided: LD_LIBRARY_PATH=/usr/lib32:/usr/lib:/mnt/vendor/lib (dmenu_ln),
  plus each script's own exports. CWD: undefined (scripts use progdir idiom).
- dmenu pause/exit/restore: dmenu does NOT pause — it TERMINATES. No in-memory
  state survives; "restore" = fresh dmenu process re-scanning dirs at startup.
- Icon refresh: NOT needed. dmenu scans APPS + Imgs at each start (proven by the
  `sw` language-rename flow which renames .sh/.png pairs while dmenu is dead).
  New <Name>.sh + Imgs/<Name>.png appear on next menu entry automatically.
- Whoami: scripts run as ROOT (whole chain uid 0; .sh files root-owned 777 on VFAT).
