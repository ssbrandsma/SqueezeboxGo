## 1. SBOM — PASS

that parses `docs/test-results/wp2u-dpkg-manifest.txt` verbatim):

- userland: 141/141 packages, 0 diff vs the measured manifest
  (trixie, all `install ok unpacked`); suite NOT snapshot-pinned (stated).
- sources: 13 pins — 8 shipped in image (linux v7.3.4, u-boot v2026.10,
  ATF v2.15.0, squeezeplay 758bc11 + 0001-0007, sdl12-compat 1.2.78,
  SDL2 2.32.10, trixie userland, repo-authored payload) + 5
  reference-only (librespot v0.8.0, slimserver 9.0.2, squeezelite,
  jivelite, tcz-jivelite). All 7 cross-checked pins match
  `docs/upstream-references/upstream-manifest.md`.
- toolchain: specified containers (`build/toolchain/Dockerfile`
  ubuntu:24.04 FLOATING base; `build/docker/Dockerfile` pinned base,
  floating apt) marked `used_for_0_2_0_exp2: false`; actual host build
  env recorded (Ubuntu 24.04, gcc-aarch64 13.3.0, mke2fs 1.47.0,
  rootless /tmp/wp2sys) with repro limits.
- artifacts + `image_git_commit` byte-equal to `releases/MANIFEST.json`.
- `releases/MANIFEST.json` deliberately untouched: its `sbom: null` is
  the historical 0.2.0-exp2 record; this SBOM is the draft a future
  manifest points at (stated in SBOM `limitations`).
