# StandaloneRadio: local Now Playing synthesis (no-Base fallback)

Date: 2026-11-17. Applies to StandaloneRadio 0.9.20 (26-file zip).
Status: deployed to RG35XX H for live verification (v2).

## Problem

With Standalone Base absent, the stock Jive Now Playing screen is dead:
selecting the home-menu "Now Playing" item silently does nothing (empty
playlist falls through to the playlist browser after 1s).

Root cause chain (all verified live on device):

1. `StandaloneBaseNowPlaying` publishes to Base at 127.0.0.1:9000.
   Without Base every claim fails (`connection refused`, 30s retries).
2. `onPublished` therefore never fires, so `player:onStage()` and
   `nativeNowPlaying:request()` never run.
3. Nothing populates the native Player: playlist stays 0, state stays
   the remote library's idle status.
4. `goNowPlaying` gates on `_playlistHasTracks()` (playlist > 0) and
   `_delayNowPlaying` opens the (empty) playlist instead.

## Fix

New module `LocalPlayerStatus.lua` synthesizes an LMS-style playerstatus
(radio: remote=1, one-track playlist, station + ICY/timed title) and feeds
it through the stock `Player:_process_status`, driving the UNMODIFIED
Now Playing window, home item, X shortcut and screensaver.

Yield behavior: every push is skipped once `baseClient:status()`
reports `hasSession`, so real Base/LMS state takes over automatically
when Base is installed. No configuration, no mode flag.

V1 scope: text + transport state. Artwork fields omitted on purpose
(stock placeholder, zero server fetches). Episode seeking disabled
(`can_seek` unset: seeks address the SlimProto server, not the local
decoder). Two fields the stock window concatenates (`playlist repeat`,
`playlist shuffle`) default to `"0"` (repeat/song off) — a nil there
aborts the whole window open (found live, fixed in v2).

## Files

- `LocalPlayerStatus.lua` — new module, drop into the applet dir.
- `StandaloneRadioApplet.wiring.diff` — wiring (require + instantiate
  + 7 callback mirrors + free). Generated by `apply-wiring.py` from the
  pristine 0.9.20 `StandaloneRadioApplet.lua`.
- `apply-wiring.py` — applies the wiring with exact-match anchors
  (fails unless each matches exactly once), CRLF-preserving.
- `test-local-player-status.lua` — host unit test for the pure
  status-table builder: `lua5.1 test-local-player-status.lua`
  (30 checks: shapes, fallbacks, preserve-through, repeat/shuffle
  defaults, episode position, no seek flag).

## Integration notes (applet repo)

- `onFirstPush` navigates WITHOUT `player:onStage()`: subscribing would
  pull the remote library's empty playlist over the synthesized state.
- Synthesis re-pushes on every radio callback (select/connect/state/
  metadata/timed/position), so a stray server status is self-healed
  within seconds. No heartbeat yet — add one if clobbering is observed
  (periodic re-subscribe by the SlimProto layer would be the source).
- `player._process_status` is convention-private (module-level function
  in `jive.slim.Player`); called via pcall, guarded by type check.
- `playlist_timestamp` is pinned per station so pushes do not spam
  `playerPlaylistChange`.
- On stop/handoff the module pushes mode=stop keeping the last track
  (LMS stop semantics); the playlist stays until real server state
  arrives.
